AimPark — How to Run Everything
================================

You need up to 3 things running at once, in separate terminals.
Plus the RFID enrollment reader, which is hardware -- section 4 covers
wiring it and flashing it.


1. BACKEND API
---------------
Folder: AimPark.API/AimPark.API

    dotnet run

Listens on:
  http://localhost:5041   (used by the admin web app)
  https://localhost:7124

Keep this running before starting the admin app or mobile app —
both depend on it.


2. ADMIN WEB APP (aimpark_admin)
----------------------------------
Folder: aimpark_admin

    flutter run -d web-server --web-port 5000

Must be port 5000 specifically — the backend's CORS policy only
allows requests from http://localhost:5000. It'll print a URL,
open it in whatever browser you like.


3. MOBILE APP (aimpark_mobile)
---------------------------------
Folder: aimpark_mobile

Step A — start an emulator (only if one isn't already running):

    flutter emulators --launch Pixel_6

  (or Pixel_8 — check "flutter emulators" for the current list)

Step B — run the app on it:

    flutter run

Step C — before running, if you're on a NEW WiFi network, check that
the API base URL still matches your machine's current LAN IP:

  File: aimpark_mobile/lib/core/constants/api_constants.dart
  Currently hardcoded to: http://192.168.100.95:5041

  To find your current IP (Windows):  ipconfig
  Look for "IPv4 Address" under your active Wi-Fi/Ethernet adapter.
  If it changed, update that file and re-run.

  Why a LAN IP and not localhost: a phone/emulator can't reach your
  PC's "localhost" — it needs your PC's actual network address.


3B. MOBILE APP ON A REAL PHONE, WIRELESSLY (no USB cable)
------------------------------------------------------------
Requirement: phone and PC must be on the SAME Wi-Fi network.
This is a one-time pairing; after that, just "connect" each session.

One-time setup (Android 11+):
  1. On phone: Settings > Developer options > Wireless debugging > ON
     (If "Developer options" isn't visible: Settings > About phone >
     tap "Build number" 7 times.)
  2. Tap "Pair device with pairing code" on the phone. It shows an
     IP:PORT and a 6-digit code.
  3. On PC:
         adb pair <ip>:<port>
     Enter the 6-digit code when prompted.

Every time you want to connect (after the one-time pairing above):
  1. On phone: open Wireless debugging — note the IP:PORT shown on
     the main screen (this is a DIFFERENT port than the pairing one).
  2. On PC:
         adb connect <ip>:<port>
  3. Confirm it's seen:
         flutter devices
     Your phone should now appear in the list.
  4. From the aimpark_mobile folder:
         flutter run
     Pick your phone if prompted.

If your phone is on Android 10 or older (no Wireless debugging menu):
  1. Connect phone via USB once, with USB debugging enabled.
  2. adb tcpip 5555
  3. Find the phone's IP (Settings > About phone > Status > IP address).
  4. adb connect <phone-ip>:5555
  5. Unplug the USB cable — it stays connected over Wi-Fi.

Don't forget: the app still needs your PC's LAN IP set correctly in
api_constants.dart (see Step C above) — wireless ADB (for deploying
the app) and the app's API connection (for talking to the backend)
are two separate network paths. If the app installs fine but can't
reach the backend, also check Windows Firewall isn't blocking inbound
connections to port 5041.


4. RFID ENROLLMENT READER (hardware: ESP32 + RC522)
------------------------------------------------------
Folder: firmware

This is the reader that sits on the admin's desk. Tapping a card on it
fills in the UID in the admin panel's "Assign RFID" dialog, so nobody
has to type a card number by hand. The barrier readers are a separate
thing -- see "MD files/ESP32_Gate_Integration.md".

Full detail is in firmware/README.md. Short version below.

Step A -- wiring, RC522 to ESP32.
The RC522 is a 3.3V part. 5V will kill it, usually not right away.

    SDA (SS) -> GPIO 5          MISO -> GPIO 19
    SCK      -> GPIO 18         RST  -> GPIO 22
    MOSI     -> GPIO 23         GND  -> GND
    3.3V     -> 3V3  (NOT 5V, NOT VIN)
    IRQ      -> leave unconnected, the sketch polls

  Go by GPIO number, not by position on the board -- the 30-pin and
  38-pin DevKits use the same GPIOs in different spots.

  Optional and safe to skip: green LED on GPIO 26, amber LED on
  GPIO 27, buzzer on GPIO 25 (LEDs through a 220 ohm resistor to GND).

Step B -- one-time PC setup
  1. Install the "PlatformIO IDE" extension in VS Code. Its first
     launch downloads a toolchain; give it a few minutes.
  2. Open the firmware folder ITSELF in VS Code, not the repo root.
     platformio.ini lives in firmware/, and PlatformIO only looks in
     the folder you opened. ("Unknown environment" means you opened
     the wrong folder.)
  3. Nothing to install by hand -- platformio.ini already pins the
     board (esp32dev) and pulls in MFRC522 and ArduinoJson.
  4. If no COM port appears when you plug the board in, install the
     CP210x or CH340 USB driver, whichever chip your board has. This
     board comes up as COM3 (CP210x).

Step C -- secrets (once per machine)

    cd firmware/aimpark_enroll_reader
    cp secrets.example.h secrets.h

  secrets.h is git-ignored, so a fresh clone doesn't have it and the
  build fails on purpose until you make it. Fill in four values:

    WIFI_SSID / WIFI_PASSWORD
        2.4GHz networks only. The ESP32 cannot see a 5GHz network at
        all, no matter how right the password is. Most phone hotspots
        default to 5GHz.

    API_BASE
        Your PC's LAN IP plus port 5041 -- the same IP the mobile app
        uses. Currently http://192.168.100.95:5041
        Not localhost: to the board, "localhost" means the board.

    API_KEY
        Issued from the API once. See Step D.

Step D -- device key (once, unless it gets revoked)
With the API running and an admin JWT in hand:

    curl -X POST http://<your-ip>:5041/api/admin/gate-devices \
      -H "Authorization: Bearer <admin JWT>" \
      -H "Content-Type: application/json" \
      -d "{ \"name\": \"Enrollment Desk\", \"gate\": 0 }"

  gate 0 means "not on a barrier". The entry and exit endpoints refuse
  a key registered this way, so this reader sitting on an open desk
  can't be used to open a gate. Copy apiKey out of the response
  immediately -- only its hash is stored, it is never shown again.

Step E -- build, flash, watch. From the firmware folder:

    pio run -e enroll_reader -t upload     (build and flash)
    pio device monitor -e enroll_reader    (serial monitor, 115200)

  If pio isn't on PATH, it's at:
    C:\Users\ADMIN\.platformio\penv\Scripts\pio.exe

  IMPORTANT -- this board does NOT reliably auto-reset into flash
  mode. Uploads usually fail once with "Wrong boot mode detected".
  The fix: the moment it prints "Connecting....", hold BOOT, tap EN,
  release BOOT. Expect to do this on nearly every upload. Also use a
  data USB cable -- plenty of cables only carry power.

  A healthy boot looks like:
    AimPark enrollment reader
    Firmware Version: 0x92 = v2.0
    WiFi: joining ....
    WiFi: up, this reader is 192.168.x.x
    Ready. Tap a card.

  And a tap looks like:
    Card: 04A2B3C4D5
      -> FREE: Card read. Not yet assigned.

Step F -- day to day
  Once flashed, the reader doesn't need a PC. Give it USB power and it
  joins WiFi and talks to the API by itself. You only need PlatformIO
  again to change the firmware or the secrets.

  In the admin panel: open a user, click Assign RFID, THEN tap the
  card. The dialog only polls while it's open, so tapping first shows
  nothing.

Common hardware problems:
  "Firmware Version: 0x00" or "0xFF"
      RC522 isn't wired right or isn't powered. Recheck the SPI pins,
      confirm it's on 3.3V. 0x00 is usually a loose SDA or SCK.
  WiFi dots that never stop
      Wrong password, or a 5GHz network.
  "could not reach the API"
      Same three causes as the mobile app: PC on a different network,
      a stale IP in API_BASE, or Windows Firewall blocking inbound
      5041.
  "device key rejected" / "not allowed to enroll cards"
      The key is wrong, revoked, or belongs to a barrier reader. Check
      GET /api/admin/gate-devices and reissue with gate 0 if needed.
  Same card fires over and over
      The card is resting on the reader. Lift it off; there's a 3s
      cooldown.


Quick order to start everything from scratch:
  1. dotnet run                                  (API folder)
  2. flutter run -d web-server --web-port 5000    (admin folder)
  3. flutter emulators --launch Pixel_6           (any folder)
     -- or -- adb connect <ip>:<port>             (for a real device)
  4. flutter run                                  (mobile folder)
  5. plug the RFID reader into USB power          (only if you're
     assigning cards -- it needs the API up first)
